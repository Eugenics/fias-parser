# ФИАС Parser

CLI-утилита на Go для распаковки локальных ZIP-архивов Государственного адресного реестра (ГАР) и импорта XML в PostgreSQL.

## Возможности

- выбор последнего локального архива `<версия>_full.zip` и последовательная обработка архивов `<версия>_delta.zip`;
- безопасная распаковка XML по регионам в `source/xml/full` или `source/xml/delta`;
- параллельный импорт XML-данных в PostgreSQL;
- Make-цели для применения миграций и генерации запросов `sqlc`;
- запись информации о загруженной версии в таблицу `version_info`;
- контроль состояний `extracted` и `imported` отдельно для полной и дельта-выгрузки;
- обработка уведомлений о скачанных full/delta-архивах из RabbitMQ с подтверждением после успешного импорта;
- прекращение импорта при ошибке XML или записи в PostgreSQL;
- запуск распаковки и импорта full/delta по cron-расписанию в Docker.

## Архитектура и модули

Приложение разделено на CLI-оркестрацию, прикладной импорт, распаковку, модели данных и инфраструктуру PostgreSQL.

| Модуль | Ответственность |
| --- | --- |
| `main.go` | Загружает конфигурацию, создаёт общий пул PostgreSQL, обрабатывает сигналы завершения и запускает сценарии импорта или распаковки. Также управляет переходами состояния версии. |
| `internal/config` | Читает `configs/config.yaml`, применяет значения по умолчанию, разбирает `exp_delta` и проверяет обязательные параметры. |
| `internal/download` | Находит архивы нужного типа и сортирует их по версии, фильтрует файлы при извлечении, проверяет `version.txt` и заменяет рабочий каталог через временный каталог. Сетевое скачивание этот модуль не выполняет. |
| `internal/events` | Читает события `download.completed` из RabbitMQ, проверяет их поля и подтверждает сообщение после обработки. |
| `internal/app` | Сканирует XML-каталоги, запускает горутину для каждого XML-файла с ограничением параллелизма, разбирает XML потоковым декодером и передаёт пакеты соответствующим обработчикам. |
| `internal/app/handlers/import` | Преобразует пакеты доменных объектов в PostgreSQL batch-запросы. Ошибки возвращаются вызывающему коду и останавливают успешное завершение импорта. |
| `internal/domain` | Содержит структуры XML-сущностей ГАР и код их декодирования. |
| `internal/repository` | Владеет единым `pgxpool`, сохраняет метаданные выгрузки и выполняет переход `extracted → imported`. |
| `internal/db` | Код запросов, сгенерированный `sqlc`. Ручные изменения следует вносить в `sql/queries/queries.sql`, затем запускать `make sqlc`. |
| `migrations` | Последовательные миграции схемы PostgreSQL, включая составную уникальность версии `(version_id, file_type)`. |
| `sql` | Исходные SQL-запросы для `sqlc` и справочное описание схемы. |

### Поток распаковки

1. Выбирается архив с максимальной версией из `fias.archives_dir`.
2. В `version_info` проверяется, не обработана ли эта версия и нет ли другой ожидающей версии того же типа.
3. Архив распаковывается во временный каталог рядом с целевым.
4. Дата из `version.txt` проверяется на соответствие версии в имени ZIP.
5. После проверки временный каталог заменяет `source/xml/full` или `source/xml/delta`.
6. Версия записывается со статусом `extracted`, путём архива и сроком действия.

### Поток импорта

1. Проверяются `version.txt` и отсутствие статуса `imported` для пары `(version_id, file_type)`.
2. Для каждого XML-файла запускается горутина; число одновременно работающих горутин ограничивает `importer.workers`.
3. Все обработчики используют один пул PostgreSQL. Запись выполняется пакетами размера `importer.batch_size`.
4. Любая ошибка чтения XML или записи batch возвращается в CLI и прерывает успешное завершение.
5. Только после обработки всех файлов статус существующей записи меняется с `extracted` на `imported`. Остальные метаданные сохраняются.

## Требования

- Go 1.25 или новее;
- PostgreSQL 16 (рекомендуемая и используемая в Docker Compose версия);
- Docker и Docker Compose — для запуска PostgreSQL и планировщика;
- для служебных целей: `golangci-lint`, `sqlc` и `migrate`.

## Быстрый старт: локальные архивы

Все команды необходимо выполнять из корня репозитория.

1. Создайте файл `deployments/.env` для PostgreSQL:

   ```dotenv
   DB_USER=fias
   DB_PASSWORD=fias
   DB_NAME=fias
   DB_PORT=5434
   FIAS_ARCHIVES_DIR=../../fias-downloader/var/data/downloads
   TZ=Asia/Novosibirsk
   FULL_SCHEDULE=0 2 * * 0
   DELTA_SCHEDULE=*/5 * * * *
   RUN_ON_STARTUP=false
   STARTUP_LOAD_TYPE=delta
   ```

   В `configs/config.yaml` укажите тот же DSN (`localhost:5434`), режим
   `rabbitmq.mode: local` и путь `fias.archives_dir` к каталогу с архивами
   `<версия>_full.zip` и `<версия>_delta.zip`. Относительный путь к архивам
   при локальном запуске вычисляется от корня репозитория, а
   `FIAS_ARCHIVES_DIR` для Compose — от каталога `deployments`.

2. Установите утилиту миграций и подготовьте базу:

   ```bash
   make tools
   make migrate-up
   ```

   `make migrate-up` запускает Compose и применяет миграции с хоста.
   Compose также запускает планировщик. Для работы с локальными архивами
   измените `rabbitmq.mode` на `local` в `deployments/parser-config.yaml`
   перед запуском Compose. Внешняя сеть `fias-downloader-network` должна
   существовать даже в этом режиме.

3. Запустите импорт из корня репозитория:

   ```bash
   make load-full
   make load-delta
   ```

   `make load-full` выбирает последний полный архив. `make load-delta`
   обрабатывает все дельта-архивы по возрастанию версии, пропуская уже
   импортированные.

### Локальный запуск с внешней PostgreSQL

Создайте `configs/config.yaml` по примеру из раздела
[«Конфигурация»](#конфигурация), запустите PostgreSQL и примените миграции.
После этого полную выгрузку можно обработать одной командой:

```bash
make load-full
```

Для дельта-выгрузки используйте `make load-delta`. Команда последовательно
обработает все локальные дельта-архивы по возрастанию даты и пропустит версии,
которые уже отмечены в БД как импортированные.

## Команды CLI

| Аргумент | Действие | Запуск |
| --- | --- | --- |
| `0` | Импорт полной выгрузки из `source/xml/full` | `go run . 0` |
| `1` | Импорт дельта-выгрузки из `source/xml/delta` | `go run . 1` |
| `2` | Распаковать последний полный архив | `go run . 2` |
| `3` | Распаковать последний дельта-архив | `go run . 3` |
| `5` | В режиме `local` — загрузить все ещё не импортированные дельты по порядку; в режиме `rabbitmq` — обработать доступные события full/delta | `make load-delta` |

Примеры запуска без Makefile:

```bash
go run . 2
go run . 0
```

Конфигурация загружается и соединение с PostgreSQL устанавливается до обработки аргумента. Поэтому база данных должна быть доступна даже при запуске без аргумента или с неизвестным значением.

## Конфигурация

При локальном запуске конфигурация читается из `configs/config.yaml`. Этот файл
исключён из Git, поскольку может содержать строку подключения с учётными
данными. В Docker используется отслеживаемый файл
`deployments/parser-config.yaml`: каталог архивов внутри контейнера равен
`/archives`, а DSN передаётся через `GAR_DATABASE_DSN`.

```yaml
database:
  dsn: postgres://USER:PASSWORD@HOST:5432/DATABASE?sslmode=disable

importer:
  batch_size: 1000
  workers: 4

rabbitmq:
  mode: local # local или rabbitmq
  url: amqp://fias:fias@localhost:5672/
  queue: fias.download.completed

fias:
  archives_dir: ../fias-downloader/var/data/downloads
  exp_delta: 168h
  imported_file_prefixes:
    - AS_ADDR_OBJ_
    - AS_ADDR_OBJ_PARAMS_
    - AS_ADM_HIERARCHY_
```

- `database.dsn` — обязательная строка подключения к PostgreSQL;
- `importer.batch_size` — размер пакета при записи в БД;
- `importer.workers` — максимальное число одновременно обрабатываемых XML-файлов;
- `rabbitmq.mode` — `local` (по умолчанию: сканирование каталога) или `rabbitmq` (события о готовых архивах);
- `rabbitmq.url` — адрес AMQP; переменная окружения `RABBITMQ_URL` имеет приоритет и обязательна в режиме `rabbitmq`, если URL не указан в YAML;
- `rabbitmq.queue` — очередь событий downloader, по умолчанию `fias.download.completed`;
- `fias.archives_dir` — каталог с архивами `<версия>_full.zip` и `<версия>_delta.zip`;
- `fias.exp_delta` — срок действия записи после распаковки в формате Go duration, по умолчанию `168h`;
- `fias.imported_file_prefixes` — префиксы XML-файлов, которые нужно извлекать из архива.

### Обновления из RabbitMQ

Downloader из соседнего проекта `../fias-downloader` публикует события
`download.completed` в очередь `fias.download.completed`. Для локального запуска
установите в `configs/config.yaml` значение `rabbitmq.mode: rabbitmq` и адрес
`amqp://fias:fias@localhost:5672/`. Каталог `fias.archives_dir` должен указывать
на архивы downloader. Затем выполните из корня репозитория:

```bash
make load-delta
```

В Docker используется `rabbitmq.mode: rabbitmq` из
`deployments/parser-config.yaml`. Укажите `RABBITMQ_URL` с учётными данными
брокера в `deployments/.env`. Compose передаёт этот файл контейнеру; Git его игнорирует.
Архивы доступны по
`fias.archives_dir: /archives`; Compose монтирует в этот каталог путь
`FIAS_ARCHIVES_DIR` из `deployments/.env`. Запустите downloader, затем соберите
актуальный образ parser и подключите его к общей сети:

```bash
make docker-build
```

Сеть `fias-downloader-network` должна существовать до запуска parser. Настройте
`DELTA_SCHEDULE` для периодического опроса очереди или установите
`RUN_ON_STARTUP=true` и `STARTUP_LOAD_TYPE=delta` для одного запуска при старте.
Команда `5` вычитывает доступные сообщения и завершается, не ожидая новых.
Расписание full в этом режиме вызывает старые команды `2` и `0`, которые
выводят сообщение о режиме RabbitMQ и не выполняют импорт.

Сообщение содержит тип `full` или `delta`, версию и `file_path`. Parser берёт
имя ZIP из `file_path` и ищет его в собственном `fias.archives_dir`, а в
`version_info` записывает исходный `file_path` из сообщения. Архив должен быть
виден обоим сервисам. Сообщения об уже импортированных версиях
подтверждаются без повторного импорта. Новая версия распаковывается, импортируется
и получает статус `imported`; только после этого сообщение подтверждается.
При ошибке сообщение возвращается в очередь, а команда завершается с ошибкой.
Другие номера CLI и соответствующие Make-цели в этом режиме не выполняют импорт.

Для проверки подключения к живому брокеру без обработки рабочей очереди:

```bash
GAR_TEST_RABBITMQ_URL=amqp://fias:fias@localhost:5672/ \
  go test ./internal/events -run TestDrainLiveRabbitMQ -count=1 -v
```

Тест создаёт отдельную временную очередь, проверяет получение и подтверждение
одного сообщения и удаляет эту очередь. Он не импортирует архивы.

## Структура данных

После распаковки данные располагаются так:

```text
source/xml/
├── full/
│   ├── version.txt
│   └── <код-региона>/*.XML
└── delta/
    ├── version.txt
    └── <код-региона>/*.XML
```

Импортер ожидает XML-файлы в подкаталогах регионов. XML-файлы, размещённые непосредственно в каталоге выгрузки, обрабатываются как регион `00`.

## Работа с базой данных

```bash
make compose-up
make migrate-up
make migrate-down
make migrate-new NAME=add_example_field
make sqlc
make compose-down
```

`make compose-up` запускает PostgreSQL и планировщик `fias-parser-scheduler`.
Планировщик подключается к внешней сети `fias-downloader-network`, поэтому
она должна существовать до запуска Compose. Compose не применяет миграции:
для этого используется `make migrate-up` на хосте.
По умолчанию полная выгрузка обрабатывается по воскресеньям в
02:00, дельта — каждые пять минут (часовой пояс `Asia/Novosibirsk`). В режиме
`local` задача full сначала распаковывает последний локальный архив, затем
импортирует его; задача delta последовательно обрабатывает все локальные
дельта-архивы. В режиме `rabbitmq` задача delta опрашивает очередь, а задача
full запускает команды `2` и `0`, которые завершаются без обработки.
Одновременный запуск двух задач блокируется.

Расписание и каталог архивов задаются в `deployments/.env`; пример приведён
в разделе [«Быстрый старт»](#быстрый-старт-локальные-архивы).

Значения `FULL_SCHEDULE` и `DELTA_SCHEDULE` используют стандартные пять полей
cron. Чтобы немедленно выполнить одну загрузку при старте контейнера, установите
`RUN_ON_STARTUP=true` и выберите `STARTUP_LOAD_TYPE=full` или `delta`. Логи
планировщика и импорта доступны командой:

```bash
docker compose -f deployments/docker-compose.yaml logs -f fias-parser-scheduler
```

По умолчанию команды миграций используют `DB_URL`. При необходимости передайте собственную строку подключения:

```bash
make migrate-up DB_URL='postgres://USER:PASSWORD@HOST:5432/DATABASE?sslmode=disable'
```

## Состояния версий

Одна версия идентифицируется парой `(version_id, file_type)`, где `file_type` равен `full` или `delta`.

- `extracted` — архив проверен и распакован, но ещё не импортирован;
- `imported` — все XML-файлы успешно обработаны.

Повторная распаковка обработанной версии запрещена. Нельзя распаковать следующую версию того же типа, пока предыдущая имеет статус `extracted`. Full и delta контролируются независимо: для обычной загрузки используйте `make load-full` и затем `make load-delta`. Для отдельных шагов распаковки и импорта используйте аргументы CLI из таблицы выше.

После добавления составного ключа необходимо применить актуальные миграции:

```bash
make migrate-up
```
